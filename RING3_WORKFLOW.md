# RING3: Workflow, Style, Tools

Prepared 2026-10-31 by the lead, carried over from the ATLAS and BENCHPROOF workflow. Read with
`RING3_CONTEXT.md`, which governs scope, rules and schedule. This file governs **how** the work is done.
Revised 2026-11-01: milestone/resume rule and two-terminal rule (D-37, D-38).

## 1. Principle: the repo is the context
- Claude Code finds its own context with glob, grep and read. Don't paste long prompts; point at files.
- `CLAUDE.md` is a map (≤ 120 lines): what, commands, hard rules, where things live, how to work.
- Detailed docs live in `docs/` and are read when a card needs them.
- **Enforce rules in code, not prose.** Every invariant becomes a test that fails loudly.
- Builder prompts are short: "Do T-02" plus anything new. The card file holds the detail.

## 3. Communication style (user preferences)
- When a prompt changes, give the **full revised prompt, ready to paste**, plus the steps to do now. Don't repaste
  unchanged prompts.
- Say **"same terminal"** or **"new terminal"** for every Claude Code prompt.
- Dense, direct, results-first. Tables for comparisons.
- Beginner-level explicit steps for setup and tooling (exact commands, where to type them, what success looks like).
- Plain English for anything judges will see.

## 4. Repository conventions
```
CLAUDE.md          # map (≤120 lines)
README.md          # judges: what, demo, how to run, replay, "Built during the hackathon" with dates
Makefile           # make, make run, make test-kernel, make clean
kernel/            # ring 0: arch/i386, core, drivers, lib, include, linker.ld
user/              # ring 3: crt0, libu (syscall wrappers), programs (agentsh executor, demo jobs, fault tests)
bridge/            # host Python: framing, Muse Spark adapter, strict JSON, spend ledger, event log, replay, fuzz
tests/             # pytest drives QEMU headless; invariant tests are tests/test_inv_NN_*.py
config/            # models.toml, budget.toml
docs/              # ARCHITECTURE, INVARIANTS, DECISIONS, STATUS, tasks/, evals/, evidence/T-xx/, context-packs/
runs/              # event logs (git-ignored)
replay/            # curated bundles judges replay (committed)
```
- Every file is created on or after 2026-10-31 in this repo. No copied code from earlier projects or tutorials.
  Intel SDM, OSDev wiki and similar are **references for facts**, not sources to paste (D-09).
- Small commits, `T-xx: <what>` plus the trailer `Builder: <model>/<effort>`. Push only on the user's say-so,
  after the secret scan.
- LF line endings (`.gitattributes`). Pinned Python deps (`uv.lock`). Record toolchain versions in evidence.
- `SETUP.md` (the user's setup runbook) lives in the claude.ai Project only, not in the repo (D-40).

## 5. Task card template (`docs/tasks/T-xx.md`)
```
# T-xx <title>
Builder: <model>/<effort> · new terminal · <when>
Goal: <one sentence>
Context: <files to read>
User does first: <setup the user must do>
Do: <numbered steps>
Don't: <exclusions; invariants at risk>
Acceptance (binary): A1..An
Evidence (docs/evidence/T-xx/): <files>
Stop and report if: <conditions>
```
A card is done only when every acceptance item passes and its evidence exists.

## 6. Engineering practices
| Practice | How RING3 applies it |
|---|---|
| Hardest risk first | The ring-3 isolation slice is in T-01, not T-02 (D-14), and comes right after the test harness (D-37) |
| Tests that boot the real kernel | pytest launches QEMU headless with a timeout, reads COM1, and exits via `isa-debug-exit`; in-kernel `ktest`s for pure logic |
| Invariants as tests | `tests/test_inv_NN_*.py`, listed in `docs/INVARIANTS.md` |
| Fuzz the boundaries | Syscall fuzzer (user program) and serial-frame fuzzer (bridge mode) with fixed seeds |
| Measure, don't assert | Eval tables are generated by code from runs; permissive-build baseline for comparison |
| Context packs | The model's system prompt is a versioned file in `docs/context-packs/`; its SHA-256 goes in the event log |
| Strict model replies | Exact schema, one action, no extra fields, no lenient parsing, no repair of model output |
| No RAG, no LLM-as-judge | The kernel decides; there's nothing to retrieve |

## 7. Daily rhythm
1. Morning: the lead reads `docs/STATUS.md` and the evidence, adjusts the day's cards. Each new card gets a
   Gemini 4 Argon pre-review before its builder session; the lead triages the findings into the card (D-42).
2. Builder: one card per **new terminal** session. Long cards commit and add a STATUS line at each milestone, so a
   fresh session can resume with "Resume T-xx from docs/STATUS.md" (D-37).
3. **Two terminals at once** (Nov 1–2, D-38, D-42): at most two, and only when the cards touch disjoint directories
   (e.g. T-01/T-02 in `kernel/`+`user/`+`tests/`, T-06 in `firmware/`+`hardware/`, T-03a in `bridge/`). Each session commits only its own paths
   (`git add <paths>`, never `git add -A` or `git commit -a`) and edits `docs/STATUS.md` only in its own row.
4. Evening: the skeptic subagent reviews the day's diff (read-only); the lead triages; fixes go on the next card.
5. Gates: **Codex Gate A, Nov 3 evening** (syscall boundary, user-pointer checks, frame parser, capability and
   confirmation paths, bridge reply validation, keys). **Codex Gate B, Nov 4 morning** (clean-clone build, replay
   reproduces decisions, README/video claims, secret scan).
6. Meta office hours: Discord #office-hours, weekdays 10 to 11 AM ET (first chance: Mon Nov 2).

## 10. Security rules (binding)
- Never open, print or hash `.env` / `.env.*`. Keys come from the environment only (`MODEL_API_KEY`).
- Keys never reach logs, the event log, test fixtures, the repo, the VGA screen or exception text.
- Never paste a key into chat or into Claude Code.
- No elevated or permission-change retries.
- Before every push: secret scan, and no user names or absolute paths in committed files or replay bundles.
