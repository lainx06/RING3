# T-19 Voice requests: push-to-talk through Muse Voice Transcribe (host side only)
Builder: Opus 5.5 / high · new terminal · worktree `~/dev/RING3-voice`, branch `voice` · D-104 · merges only on the
user's word

Goal: the operator can **say** a request ("RING3, set the fan to 100 %") instead of typing it. The webcam's built-in
microphone (Logitech C922) records it on Windows, **`muse-voice-transcribe-1.0`** turns it into text (documented:
`POST https://api.meta.ai/v1/asr/transcribe`, multipart `request` JSON + `audio` WAV, $0.18 per hour,
https://dev.meta.ai/docs/api-reference/voice/transcribe), the operator sees the transcript and **presses Enter to send
it** as the request. Nothing in the kernel changes: the request travels exactly as a typed one, and the kernel decides
every action as before.

Context: `CLAUDE.md`, `docs/INVARIANTS.md` (INV-05 human confirmation, INV-09 keys, spend), `docs/DECISIONS.md` D-23,
D-80 (the fresh-capture helper pattern), D-104; `tools/witness_capture_win.py` (the pattern for a Windows helper),
`tools/eval/e4_agent.py` (how a host tool already types into the console), `bridge/ring3bridge/models/`.

## Rules
- **Confirmations stay keyboard-only.** The voice path never sends while a `CONFIRM:` prompt is pending, never sends a
  line that is only y / n / yes / no (in any case or punctuation), and every transcript needs the operator's Enter
  before it is sent. Tests for all three.
- **The key is read only in `models/`:** the transcription call is a new adapter there, reusing the transport and
  redaction; key/header never in events, blobs, exceptions or the screen.
- **Reserve before every call:** the recording's duration (capped at 15 s) at the published per-hour price from
  `config/models.toml` (official pricing page; stop if it isn't published).
- **The transcript is untrusted text:** it goes to the console as a request line, like typing (bounded length, printable
  ASCII only, control characters stripped); it never becomes a command to the host shell or the bridge.
- No hidden listening: recording happens only while the operator holds the push-to-talk (or between two key presses),
  with a visible "REC" indicator and a 15 s cap.

## Design (the builder may refine it; report changes)
1. **Windows audio helper** `tools/voice_capture_win.py` (like the camera helper): records from the C922 microphone (or
   the default input) into a WAV (16-bit PCM, mono; the sample rate the docs accept) on a request file in
   `RING3_WITNESS_DIR` or a sibling folder; a `--selftest` that records 2 s and prints the level and the duration.
2. **`ring3 console`** (WSL): runs the cell image like `make run-cell` but with COM1 connected to this tool, which
   proxies the operator's keyboard and the screen output unchanged, plus a push-to-talk key (e.g. F2, or a line `/v`).
   On push-to-talk: record, reserve, transcribe, show `heard: "<text>"  Enter = send, Esc = discard`.
3. Strip a leading wake word ("RING3," / "ring three,") from the transcript before sending; the request text is what
   the model sees.
