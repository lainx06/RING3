# T-01B Link smoke test: Arduino → WSL → QEMU COM3
Builder: Opus 5.5 / high · new terminal · Nov 1 evening, **only after T-01's kill check passes** (D-31)

Goal: prove early that the Uno reaches the kernel as COM3 and bytes flow both ways, before any real firmware.

Context: `docs/ARCHITECTURE.md` §3a; `docs/DECISIONS.md` D-20, D-31, D-39.

User does first (Windows + Ubuntu, done during T-01): usbipd-win installed; Uno bound and attached
(`usbipd bind --busid <id>` once, as administrator; `usbipd attach --wsl --busid <id>` after each replug); user in
the `dialout` group; the board visible as `/dev/ttyACM0` (or `/dev/ttyUSB0` on a CH340 board); `arduino-cli` with
`arduino:avr` installed in Ubuntu (D-42). T-06 may already have flashed `ring3cell`; this card reflashes the echo
sketch, and the user puts `ring3cell` back afterwards.

## Do
1. `firmware/echo/echo.ino` (trusted, hand-written): 115200 baud; echoes each byte + 1, and prints `ECHO READY`
   at boot. Compile it (`arduino-cli compile --fqbn arduino:avr:uno firmware/echo`) and give the user the exact
   `arduino-cli upload` command for the attached port, plus the one to put `ring3cell` back. **You never upload.**
2. Kernel: a polling COM3 (0x3E8) driver variant and a `KTEST_LINK=1` build that waits for `ECHO READY`, sends
   `0x00..0x0F`, and checks 16 replies of byte+1 within 2 s.
3. `make run-link` adds `-serial <port>` (default `/dev/ttyACM0`, overridable) as the third serial port (record
   the exact QEMU command).
4. Note the Uno resets when the port opens; measure the time from open to `ECHO READY`.
5. Record which IRQ QEMU gives COM3 (expected IRQ 4, shared with COM1, D-39a), e.g. from `info qtree` in the QEMU
   monitor. Polling is enough for this card; T-04 handles the shared IRQ.

## Don't
Flash, write to the board, read `.env`, push, or build the real firmware (T-06).

## Acceptance (binary)
- A1 `KTEST_LINK` passes 3 runs in a row; transcript saved.
- A2 Reset-to-ready time recorded.
- A3 Exact usbipd + QEMU commands and the COM3 IRQ recorded in `docs/evidence/T-01B/README.md`.

## Stop and report if
usbipd can't attach the Uno, `/dev/ttyACM0` doesn't appear, or QEMU can't open it. The lead then switches to the
D-20 fallback (QEMU on Windows with `-serial COM3`).
