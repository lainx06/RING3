# T-01B Link smoke test: real ring3cell firmware → WSL → QEMU COM3
Builder: Opus 5.5 / high · new terminal · Nov 2 morning, after T-02F (both touch `kernel/`) · revised D-51

Goal: prove the Uno reaches the kernel as COM3 and real frames flow both ways, using the **real `ring3cell`
firmware** (no echo sketch, no reflashing), before T-04 builds the driver on this path.

Context: `docs/ARCHITECTURE.md` §3a, §4; `hardware/protocol.md`; `firmware/ring3cell/protocol.h`;
`docs/DECISIONS.md` D-20, D-31, D-39a, D-47, D-48, D-51; `docs/evidence/T-06/README.md`.

User does first: the Uno attached to Ubuntu (`/dev/ttyACM0`, the `usbipd --auto-attach` window open),
`sudo chmod a+rw /dev/ttyACM0`, `ring3cell` flashed (T-06), the module switched **on** (D-48 rule), no monitor or
`cellctl.py` holding the port.

## Do
1. A **polling** COM3 (0x3E8) driver variant used only by a `KTEST_LINK=1` build: program 115200 8N1; wait up to
   3 s for the first valid `STATE` frame (the Uno resets when QEMU opens the port, ~1.6 s, T-06 evidence); decode
   ≥ 20 consecutive `STATE` frames with the kernel's own COBS/CRC code and the frame layout from `protocol.h`
   (include it if it is freestanding-clean; otherwise mirror it and add a test that compares both); send `PING`
   frames and require the firmware's `ack` counter to advance; print a summary; exit via `isa-debug-exit`.
2. `make run-link` (and `make test-link`) adds `-serial <port>` as the **third** serial port (default
   `/dev/ttyACM0`, overridable). Record the exact QEMU command.
3. Record which IRQ QEMU gives COM3 (expected IRQ 4, shared with COM1, D-39a), e.g. via `info qtree` in the QEMU
   monitor. Polling is enough here; T-04 handles the shared IRQ.
4. Measure: time from QEMU start to the first `STATE`; the `STATE` rate seen by the kernel (expect ~20 Hz).
5. The fan must not move at any point (no `FAN` frames are sent; the D-48 pull-down holds it through the reset).

## Don't
Send `FAN`/`SERVO`/`ESTOP_RESET` frames, flash or upload, touch `firmware/` or `bridge/`, read `.env`, push.

## Acceptance (binary)
- A1 `make test-link` passes 3 runs in a row with the real board: ≥ 20 valid `STATE` frames, `ack` advancing on
  `PING`; transcripts saved.
- A2 Reset-to-first-`STATE` time and the kernel-observed `STATE` rate recorded.
- A3 Exact usbipd + QEMU commands and the COM3 IRQ recorded in `docs/evidence/T-01B/README.md`.
- A4 Default `uv run pytest` unaffected (the link test is opt-in, marked `hw`, skipped without the board).

## Stop and report if
`/dev/ttyACM0` can't be opened by QEMU, no valid `STATE` arrives within 3 s, or frames decode in `cellctl.py` but
not in the kernel. The lead then decides on the D-20 fallback (QEMU on Windows with `-serial COM3`).
