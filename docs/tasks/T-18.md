# T-18 Graphics screen (experimental branch; merges only if it beats the text screen with every check green)
Builder: Fable 5.1 / high · new terminal · worktree `~/dev/RING3-gfx`, branch `gfx` · D-101 · **main stays frozen at

Goal: an optional **pixel graphics** screen for the QEMU window: the same screen model as T-08/T-14 (status bar,
decision banner, console, the cell panel, the decision ticker), drawn at 1024x768 with real shapes. A rotating fan with
smooth blades, a round dial with a needle, the sensor beam, the E-stop lamp, and readable text, so the video looks like
a real control-room monitor. **Text mode stays the default**: every existing test, the evals and the replays keep running
on it unchanged. Graphics is a boot option (Multiboot command line `gfx=1`, `make run-cell-gfx`).

Context: `docs/tasks/T-08.md`, `docs/tasks/T-14.md`, `docs/design/astra-ui-spec-raw.md`, `docs/ARCHITECTURE.md`
(paging, memory map), `docs/DECISIONS.md` D-66a, D-94, D-98, D-101; QEMU's standard VGA (Bochs VBE/DISPI interface)
and PCI configuration-space docs for facts only (D-09: no code copied from tutorials, wikis or other kernels).

## Design (facts from the official QEMU/Bochs/PCI docs; record the sources in the evidence)
- **Mode set:** QEMU `-vga std` via the Bochs DISPI index/data ports: 1024x768, 32 bpp, linear framebuffer. Find the
  framebuffer's physical address from the VGA device's PCI BAR0 (config space through ports 0xCF8/0xCFC; check the
  vendor/device IDs). If the device or the mode isn't there, log it and **stay in text mode**: never panic, never a
  blank screen.
- **Mapping:** map the framebuffer into a kernel-only virtual window (supervisor pages, not user-accessible,
  write-combining not required). A ring-3 access to that window must fault and kill only that process (INV-06): test it.
- **Font:** text needs glyphs. Read the 8x16 font the VGA BIOS has already loaded into VGA plane 2 **before** switching
  modes (hardware data, not copied code), and draw it scaled (x1 or x2). If that read isn't reliable, stop and report;
  don't paste a font from the internet.
- **Drawing:** a back buffer in kernel memory; primitives (filled rectangle, line, circle/arc, text) in integer
  maths; redraw only the regions that changed; copy those to the framebuffer. Rendering stays where T-08 put it
  (outside interrupt context) and must keep the tick lease on time: measure it; **render ≤ 2 ms per tick worst case**,
  otherwise reduce the frame rate (for example redraw the panel every 3rd tick), and report.
- **Same data, same rules:** it reads the same snapshot as the text screen (no new state); nothing moves without a real
  value (the fan's rotation rate comes from the board-reported duty, frozen when halted); every state has a word (never
  colour alone); original design, no franchise symbols or fonts (D-66a); no banned words.
- **No change** to `decide()`, policy state, the syscall gate, `uaccess`, the frame parsers, COM1/COM2/COM3 output, the
  event log, the bridge or the firmware. Policy hash unchanged.

## Do
1. A host-side pixel renderer for the screen model (the same C code built for the host) with golden-image tests: a
   hash of the framebuffer for idle, fan 60 (fixed frame), tainted ASK, E-stop latched, presence and stale; and a fan
   test (no motion at 0 / latched; faster at 80 % than 40 %).
2. The kernel side: PCI scan, mode set, mapping, font read, back buffer, damage copy; the `gfx=1` boot option and
   `make run-cell-gfx`; graceful fallback to text.
3. QEMU tests: boot with `gfx=1`, take a `screendump` PNG, check that its pixels match the host golden render for the
   idle state; a ring-3 program touching the framebuffer window gets PROC_FAULT, with 0 PANIC; the default (text) suite
   unchanged and green.
4. Evidence: PNGs of every state from the sim cell, the render timings, the sources used for the hardware facts.
