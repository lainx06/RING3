# T-06 Work-cell wiring guide and Uno firmware
Builder: Opus 5.5 / high · **second terminal**, Nov 1, once T-01 has made its first commit (D-42) · user wires
and flashes the same afternoon

Goal: a wiring guide the user can follow part by part, a bring-up sketch that proves each part works, and the
hand-written work-cell firmware (the second safety layer) that speaks the RING3 frame format, enforces its own
clamps, presence cutoff, E-stop interrupt and watchdogs, and streams telemetry every 50 ms.

Context: `CLAUDE.md`; `docs/ARCHITECTURE.md` §3a (parts, frames, firmware rules, power, pin budget) and §4 (frame
format, CRC); `docs/INVARIANTS.md` rule 13; `docs/DECISIONS.md` D-19, D-21, D-24, D-25, D-30, D-31, D-34, D-39b,
D-41f, D-42, D-43.

User does first: nothing for steps 1–5. Before step 6: the Uno attached to Ubuntu (`/dev/ttyACM0`, or
`/dev/ttyUSB0` on a CH340 board) and `arduino-cli` installed in Ubuntu with the `arduino:avr` core (D-42).

## Do
1. **Pin table first** (`hardware/wiring.md`). Assign every pin before any code (D-43): E-stop button on
   **D2 (INT0)**, HC-SR04 **ECHO on D3 (INT1)** (TRIG on any free digital pin), servo on **D9**, fan PWM (L293D
   EN1) on **D5 or D6 only** (Timer0; D10 is lost to the Servo library's Timer1, D3/D11 share Timer2 with
   `tone()`). L293D IN1 and IN2 are **hard-wired** to 5 V and GND (one direction, no Uno pins). LCD1602 in 4-bit mode
   (RS, E, D4–D7) with RW hard-wired to GND. Buzzer and RGB on plain digital pins. D0/D1 stay free (USB serial).
   Expected total: 15 of 18 usable pins. Note which pins have PWM and which timer each uses.
2. **Wiring guide** (`hardware/wiring.md`), written for a beginner, one part per section, **in the D-41f order:**
   E-stop → presence sensor → servo → fan (target 90 min for these four), then LCD, buzzer, RGB. Each section: the
   parts from the kit, each wire as "from → to", and a "check" line the bring-up sketch confirms. **Power (D-43,
   replaces "both rail jumpers at 5 V" in D-34):** the breadboard power module (USB charger) sets **one** rail to
   5 V (the motor rail: L293D pin 8 VCC2 and the servo); the other rail's jumper is **OFF** and that rail is fed
   from the Uno's 5 V pin (logic: L293D pin 16 VCC1, sensor, LCD, buzzer, RGB). **All grounds common.** Never
   connect the Uno 5 V pin to a rail the module also drives. 1000 µF across the servo supply (D-19). Tell the user
   to check the module's jumper positions against its silkscreen `[UNVERIFIED]` for their module. **Presence
   sensor faces a fixed backstop** (a book or box 20–40 cm away on the desk) so "clear" is a real reading. The
   E-stop uses the kit's normally-open push button with `INPUT_PULLUP` (pressed = LOW). State the honest
   limitation: a real E-stop is normally closed, so a broken wire here does **not** trigger a stop. **Bring-up
   checkpoint:** after the first four parts (E-stop, sensor, servo, fan), the user flashes and runs `bringup`
   before wiring the LCD, buzzer and RGB.
3. **Protocol** (`hardware/protocol.md` + `firmware/ring3cell/protocol.h`, the single source for T-04): frame
   type codes and exact byte layouts for `FAN`, `SERVO`, `LCD`, `ALARM`, `PING`, `ESTOP_RESET` (kernel → device)
   and `STATE` (device → kernel), using the §4 frame format (COBS, `0x00` delimiter,
   `type u8 | seq u16 LE | len u16 LE | body | crc16 LE`, CRC-16/CCITT-FALSE, check value `0x29B1`). Flag bits
   in `STATE.flags`: watchdog reset seen, clamp applied, bad frame seen, E-stop latched, presence fault latched,
   link lost. Max frame size small enough for the Uno's 2 KB RAM; state it: on `__AVR__` the frame body limit is
   the largest device frame (`LCD`, about 17 B, D-43), while host tests may use a larger constant for the COBS run
   cases.
4. **Frame code, host-tested.** `firmware/ring3cell/frame.h` + `frame.cpp`: COBS encode/decode, CRC-16 and frame
   checks as plain C++ with **no Arduino headers**, so `make -C firmware test` (its own `firmware/Makefile`)
   compiles them on the host with clang++ and runs `firmware/test/`. Tests: CRC check value; COBS round-trips
   (zero bytes, runs of 253/254/255 non-zero bytes, max frame); rejection of bad CRC, truncated, oversize,
   unknown type and wrong body length; clamp functions (servo 15–165°, fan ≤ 80 %). Also write the same vectors
   to `firmware/test/link_vectors.txt` so T-03a and the kernel can check against them.
5. **Sketches.**
   - `firmware/bringup/bringup.ino`: human-readable checks over Serial at 115200, one part at a time in the
     wiring order (prints button state, distance in mm, sweeps the servo 60→120→90, ramps the fan 30→100 % in 10 %
     steps for 1 s each and asks the user at which duty it first spins, writes "RING3 BRINGUP" on the LCD, beeps,
     cycles the RGB). Parts not wired yet are skipped with a note. The user opens it with
     `arduino-cli monitor -p <port> -c baudrate=115200`. **Record the minimum spinning duty** (the L293D drops
     about 2 V, D-43); the lead adjusts demo duties and limits from it.
   - `firmware/ring3cell/ring3cell.ino` (+ `frame.*`, `protocol.h`): the ARCHITECTURE §3a firmware. Boots into the
     **safe state** (fan off, servo 90°, LCD "SAFE - waiting for kernel"). Applies its own clamps and reports
     clamping in `flags`. **E-stop on INT0 (D-43):** the ISR sets the latch and calls `digitalWrite(FAN_EN, LOW)`,
     which also disconnects the timer's PWM output (writing the port bit alone would not); every `analogWrite` to
     the fan happens with interrupts off and only if the latch is clear; and every `loop()` pass forces the fan
     enable low while the latch is set or the button reads pressed. Only `ESTOP_RESET` with the button released
     (stable for 50 ms) clears the latch. **Presence cutoff:** distance < 100 mm, **or no echo on 3 readings in a
     row while the fan runs** (fail closed, D-43), → fan off within one loop pass, latched as a fault until the
     next valid `FAN` command with a valid clear reading. **Echo timing** on INT1 (D3, `CHANGE`) with `micros()` and
     a 30 ms timeout; never `pulseIn()`. **Watchdogs:** capture the reset cause from `MCUSR` (and `r2` when the
     bootloader passes it) in an early `.init3` hook into a `.noinit` variable, clear `MCUSR` and disable the
     watchdog there, then `wdt_enable` at the end of `setup()` and reset it in `loop()`; report "watchdog reset
     seen" in `flags`. **Link watchdog:** 1 s without a valid kernel frame → safe state + alarm. **Non-blocking:** no
     `delay()`, no `pulseIn()`, no `tone()` (the active buzzer is switched with `digitalWrite`), no `lcd.clear()` or
     `lcd.home()` outside `setup()`: the LCD is rewritten only when a line changes, as a 16-character space-padded
     line after `setCursor`. All string literals in `F("...")`. `STATE` every 50 ms. LCD shows state and the last
     command; buzzer + RGB show alarms (always with LCD text).
   - Compile both with `arduino-cli compile --fqbn arduino:avr:uno --warnings all` and record flash/RAM use.
     **You compile; you never upload.**
6. **Hardware checks (user present).** Give the user exact commands to upload `bringup` and then `ring3cell`
   (`arduino-cli upload -p <port> --fqbn arduino:avr:uno firmware/<sketch>`; the user runs them).
   `tools/cellctl.py` (stdlib only: `termios`, `tty`, `os`, `time`): opens the port in **raw mode** (`tty.setraw`,
   8N1, 115200, no flow control, `VMIN=0`/`VTIME=1`), **waits for the first valid `STATE` frame** after opening
   (the Uno resets on open), then sends frames, decodes `STATE`, and runs the A5 checks with a prompt for each
   manual action ("press the E-stop now"). Test tool only: never run it while QEMU has the port open.
7. Evidence + the T-06 row in `docs/STATUS.md`.

## Don't
- Upload or flash anything, or run `arduino-cli upload` (the user does, D-20, D-42).
- Copy firmware or library code from tutorials, earlier projects (Radar, BENCHPROOF) or the internet (D-09). The
  standard Arduino `Servo` and `LiquidCrystal` libraries may be used as libraries; record their versions.
- Use `delay()` in `ring3cell` or loosen a clamp, cutoff or watchdog to make a test pass. Stop and report.
- Touch files outside the paths above, read `.env*`, push, or install plugins/hooks.
- Build the printable gauge: it moves to T-07, where the ArUco markers are needed (D-42).

## Acceptance (binary)
- A1 `hardware/wiring.md` has a complete pin table with no conflicts (D2 = INT0 E-stop, D3 = INT1 echo, servo D9,
  fan PWM on D5 or D6, L293D IN1/IN2 and LCD RW hard-wired, D0/D1 free), the D-43 two-rail power layout, the
  sensor backstop, and every part has wiring + a check line, in the D-41f order.
- A2 `make -C firmware test` passes (CRC, COBS, rejection and clamp cases).
- A3 `bringup` and `ring3cell` compile for `arduino:avr:uno` with no warnings from our code; RAM use < 75 %.
- A4 (user present) Bring-up transcript shows every wired part responding (first after the four safety parts,
  then after the rest); parts not yet wired are listed; the fan's minimum spinning duty is recorded.
- A5 (user present, `ring3cell` flashed, `tools/cellctl.py`): `STATE` arrives at 18–22 Hz; `FAN 100` →
  reported 80 with the clamp flag; `SERVO 170` → reported 165; a bad-CRC frame is rejected and flagged; E-stop
  press → fan 0 in the next `STATE` and the latch holds until `ESTOP_RESET` with the button released; a hand
  < 100 mm while the fan runs → fan 0 and the presence fault latched; ECHO wire unplugged while the fan runs →
  fan 0 within ~150 ms and the presence fault latched; E-stop pressed while a `FAN` command is being sent in a
  tight loop → fan stays 0; no frames for 1 s → safe state + alarm.
- A6 `grep` finds no `delay(`, `pulseIn(`, `tone(`, or `lcd.clear(`/`lcd.home(` outside `setup()` in
  `firmware/ring3cell/`; `wdt_enable` and the `.init3` reset-cause hook are present.
- A7 Every commit has the `Builder:` trailer and touches only this card's paths.
