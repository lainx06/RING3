# T-01 Boot, interrupts, memory, tests, and the ring-3 isolation slice
Builder: **Fable 5.1 / high** · new terminal · Nov 1 (D-10, D-14) · revised 2026-11-01 by the lead (D-37)

Goal: a freestanding i386 kernel that boots in QEMU, handles exceptions and the timer, runs an automated headless
test suite, and proves the hardware boundary early: a ring-3 program can make a system call, and a ring-3 fault or
infinite loop ends only that program while the kernel keeps running.

## Do
1. **Repo (minimal).** `git init`; check the system date is ≥ 2026-10-31 before the first commit (stop if not).
   `.gitattributes` (LF), `.gitignore` (`build/`, `runs/`, `.env*`, `__pycache__/`, `.venv/`), `pyproject.toml`
   (uv, Python 3.12, dev deps: pytest, ruff only), `Makefile`. `.claude/settings.json`:
   - **deny:** reading `.env*`, `git push`;
   - **allow** (so the user isn't approving every build): `make` targets, `uv sync`, `uv run pytest`, `uv run ruff`,
     `qemu-system-i386`, `tools/*.sh`, `git add/commit/status/diff/log`.
   Check Claude Code's permission-rule syntax in its official docs; don't guess. Commit the planning docs first.
2. **Toolchain check.** `tools/check-toolchain.sh` prints clang, ld.lld, make, QEMU, gdb, python, uv versions and
   compiles a 1-line freestanding object for `i686-unknown-none-elf`. If that target fails, switch to
   `gcc -m32` (multilib) per D-03 and record why in DECISIONS (as a builder-proposed entry for the lead).
3. **Boot.** Multiboot v1 header, 16 KiB boot stack, `kmain(magic, mbi)`; linker script at 1 MiB. Build flags:
   `-ffreestanding -nostdlib -fno-pic -fno-stack-protector -mno-sse -mno-mmx -mno-80387 -O2 -g -Wall -Wextra -Werror`
   (adjust only with a recorded reason). Verify QEMU loads it with `-kernel`.
4. **Console.** COM1 polling driver (init 115200 8N1, IER = 0), `printk` supporting `%s %c %d %u %x %p %%` (no
   floats). Boot banner: `RING3 <version> build <short-hash>`, memory total from the multiboot map.
5. **Descriptors and faults.** GDT (kernel/user code+data, TSS). IDT with stubs for vectors 0–31 (with/without
   error code), IRQ 0–15 remapped (PIC to 0x20/0x28), and `int 0x80` as the only DPL-3 gate. Common handler with a
   saved register frame. CPL-0 exception → `panic()` dump (vector, error code, EIP, CS, EFLAGS, CR2, general
   registers) then halt; test builds exit QEMU with a failure code. No triple faults, no reboot loops (`-no-reboot`).
6. **Timer.** PIT 100 Hz *(prov.)*, tick counter, `sti`. Uptime visible in tests.
7. **Test harness (early, so everything after is tested).** `tests/qemu.py`: start QEMU headless with a timeout,
   capture COM1, return output and exit code; record the exact QEMU command in evidence. Tests now: boot banner
   within 5 s; ticks advance; deliberate CPL-0 panic build prints the dump and exits with failure; any unexpected
   `PANIC` fails the test (INV-12). Minimal `KTEST=1` mechanism (`KTEST <name> PASS|FAIL`, summary, exit through
   `isa-debug-exit`). `make run`: interactive boot with COM1 on the terminal.
   **→ Milestone M1** (target Nov 1, 2 PM ET): A1, A4, boot/tick tests green. Commit + STATUS line.
8. **Isolation slice** (no scheduler; programs run one after another from a kernel loop):
   - Physical frames: a simple frame allocator from the multiboot memory map (kernel image and low memory
     reserved). Bitmap is fine; this is the one in step 9 too.
   - Paging on with **`CR0.WP` set**: low 16 MiB *(prov.)* identity-mapped **supervisor-only**; user programs
     use the fixed flat layout (D-41): code + rodata pages at `0x40000000` **read-only**, data + bss on the
     following page-aligned pages **writable**, and a 16 KiB stack below `0x7FFFF000` (writable), all
     user-accessible, with an unmapped guard page below the stack.
   - **Before each program:** fresh, zeroed user frames (nothing carries over from the previous program) and a
     TLB flush (reload `CR3`) after the user mappings change.
   - Enter ring 3 with `iret` (EFLAGS: IF = 1, IOPL = 0, set explicitly); `TSS.esp0` points to a kernel stack.
   - Minimal syscalls: `0 exit(code)`, `1 cons_write(buf, len)`, and a test-only `uread(buf, len)` that writes
     into a user buffer, all through the user-pointer check, in this order: length cap, `ptr ≥ USER_BASE`,
     **`ptr ≤ USER_TOP`** (so the next subtraction can't wrap), `len ≤ USER_TOP − ptr`, then a page walk of every
     spanned page for `P|U`, plus `W` for writes.
   - **Abandoning a program** (CPL-3 fault, `LIMIT` from the timer, or `exit`): send the PIC EOI first when inside
     an IRQ handler, then return to the kernel loop through a context the loop saved before entering ring 3 (no
     unwinding through the trap frame), so the kernel stack and the timer stay healthy for the next program.
   - Embedded test programs (flat binaries in the D-41 layout, linked at `0x40000000`):
     `hello` (prints, exits 0; the kernel logs the CPL seen at syscall entry), `kwrite` (writes to `0x00100000`),
     `priv` (executes `cli`), `spin` (infinite loop), `badptr` (expects `-EFAULT` for: a kernel address, an
     address above `USER_TOP` (e.g. `0xC0000000`), an unmapped address, a buffer that starts mapped and runs into
     the unmapped guard page, a wrap-around length, and `uread` into its own read-only code page; then exits 0).
     `hello` also writes and reads back a global variable (proves the writable data page).
   - Fault from CPL 3 → print `PROC_FAULT pid=<n> vector=<v> eip=<x>`, end that program, continue the loop.
   - A ring-3 program that runs past a tick budget (100 ticks *(prov.)*) is ended with `LIMIT` (the timer IRQ
     arrives while CPL = 3; the kernel abandons the program and returns to its loop).
   - After all programs: print `KERNEL ALIVE uptime=<ticks>`.
   - pytest test for the transcript (A5).
   **→ Milestone M2 = kill check K1–K4** (by Nov 1, 9 PM ET). Commit + STATUS line + `docs/evidence/T-01/isolation.txt`.
   **Report to the user immediately when K1–K4 pass or fail**, then continue.
