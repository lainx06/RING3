# T-16 Vision witness: Muse Spark reads the gauge zone from the camera
Builder: Fable 5.1 / high · new terminal · worktree `~/dev/RING3-t16`, branch `t16` · D-98 · merges only on the
user's word

Goal: the camera witness works on the real cell, using a Meta model that can see. After a gauge move, the bridge sends
the rectified gauge crop to **Muse Spark (`muse-spark-1.3`, image understanding, documented at
https://dev.meta.ai/docs/image-understanding)**, which says which printed **zone** the black arm points at. RING3 compares
that with the commanded zone and reports PASS / FAIL / CAN'T VERIFY back to the agent as an observation (D-22, D-29).
It still never changes a kernel decision and never sends a link frame. SAM stays in the code as the other backend
(`--witness-backend sam|vision`); vision becomes the default only if its zone check passes on hardware.

D-29, D-72, D-77, D-80, D-83, D-98; `bridge/ring3bridge/witness/`, `bridge/ring3bridge/models/`,

## Rules (all existing invariants hold)
- The key is read only in `models/`: the image call is a new adapter in `models/` reusing the existing transport,
  redaction and reservation path (don't let it drift from `muse_spark.py`'s redaction).
- **Reserve before every call**, with a worst-case estimate: the image tokens (from the docs, or the documented
  `input_tokens` endpoint; if neither gives a number, reserve a stated ceiling and mark it `[UNVERIFIED]`) plus
  `max_output_tokens`, at the prices in `config/models.toml` taken from the official pricing page (stop if they aren't
  published).
- Only fresh frames (D-80 proof); the image sent is the rectified crop of the dial alone (no markers, no desk), at most
  1280 px on its long side, JPEG.
- **Model output is data:** the reply must be exactly `{"zone": "<Z>", "arm_visible": true|false}` with `<Z>` one of
  `OUT_LOW`, `LOW`, `MID`, `HIGH`, `OUT_HIGH`, `UNSURE`. No extra fields and no lenient parsing (use the documented
  structured-output feature if it exists; validate strictly either way). Anything else is CAN'T VERIFY: VISION_FORMAT.
- The prompt is a versioned context pack, `docs/context-packs/witness-vision-v1.md`, with its SHA-256 logged per call. It
  describes the printed gauge (zones, labels, the black arm, the boundary bands) and asks for the zone only, never an
  angle.

## Verdict
The commanded angle maps to the expected zone from the gauge's printed zone edges in `hardware/gauge/` (the kernel range
30-150). Within the boundary band of a zone edge (as printed; at least ±5°), it's CAN'T VERIFY: BOUNDARY, with no model
call. Otherwise: PASS if the reply zone equals the expected one and `arm_visible`; FAIL if it's a different definite zone
and `arm_visible`; CAN'T VERIFY (UNSURE / NOT_VISIBLE / VISION_FORMAT / STALE_FRAME / NO_MARKERS / SPEND) otherwise.
Logged with the frame hash, the reply blob and the pack hash.

## Zone check (replaces the angle calibration for this backend)
`ring3 calibrate --witness-backend vision`: commands 50, 90, 130, 90, 50, 130 (2 per zone, away from the edges) through
the kernel as calibration does now, one frame each, at most 6 images. The vision witness is enabled for the session only
if **6/6 PASS**; otherwise it is disabled with the reason (fails closed). Saved like `calibration.json`.
