## Design rules from the Gemini review (D-45; binding, each needs a test)
- **R1 Two-phase confirmation.** A call that needs a human answer makes `decide()` return `CONFIRM_PENDING` and
  record the pending call in `next`; nothing executes. The later answer or timeout event **re-runs every rule**
  (caps, taint, limits, interlock, stale, E-stop) at the answer's tick; only then `ALLOW` + `CONFIRM_YES`, or a
  deny. A hand, stale data or E-stop appearing during the wait denies the call even after "y".
- **R2 Quotas are policy state driven by tick events.** The action quota is **paused while a confirmation is
  pending** (the 30 s confirmation timeout bounds that wait); the request quota never pauses. Keep quotas and
  leases as **start/last-change ticks, not per-tick counters**, so a routine tick that changes nothing leaves the
  state unchanged (the tape can then skip silent ticks in T-03b).
- **R3 `uaccess` runs before `decide()`.** The syscall event carries `uaccess_ok`; `decide()` returns
  `DENY_FAULT` (`-EFAULT`) for it **without changing any state** (no taint, no ramp baseline, no prompt). The page
  walk checks `P|U` (plus `W` for kernel writes into user memory) at **both the PDE and the PTE**.
- **R4 Ramps and steps have real baselines.** Initial state: servo 90° (the firmware's park angle), fan 0. A fan
  increase is ≤ 20 points per command **and** needs `tick − last_fan_change ≥ increase × HZ / 20`; decreases are
  always allowed. Servo: ≤ 30° from the last allowed angle and ≥ 200 ms since it.
- **R5 Unsigned and argument-first.** Pointers and lengths are `uint32_t`. `len == 0` still validates the page at
  `ptr`. `decide()` checks argument ranges first (`duty`, `deg`, `line`, object `id`; negative = out of range) →
  `DENY_ARG` (`-EINVAL`) before any other rule.
- **R6 String copies** (`cell_lcd` text, any NUL-terminated input) copy byte by byte up to the maximum, validating
  each new page before its first byte is read; unterminated → `-EINVAL`, unmapped → `-EFAULT`, never a kernel fault.
- **R7 Request boundaries are events.** `EXEC_START` (program id, caps, quota limits) and `EXEC_END` (exit code,
  fault vector or `LIMIT`) are on the tape; `decide()` resets per-request state on `EXEC_START` and keeps `seq`,
  the E-stop latch and telemetry across requests.
- **R8 Silent decisions.** `decision` has an "audit or not" flag: routine ticks and telemetry update state silently
  (no `seq`, no audit line). `AUTO_HALT` sets the commanded motion state to halted in `next`, so it's audited once
  per hazard, not every tick.
- **R9 Trap exit.** The skeptic pre-pass confirms: PIC EOI is sent before any kill on IRQ 0, `TSS.esp0` points to
  its own kernel stack, and abandoning a program restores the saved `exec_run` context (D-41b).
- **R10 Console.** Drain COM1's receive FIFO and the line buffer right before printing `CONFIRM:` (type-ahead
  can't answer a prompt). `estop reset` clears the latch only when the latest telemetry is valid, fresh and shows
  the button released; otherwise `DENY_ESTOP`.

## Order of work (risk first; commit + STATUS line at each milestone)
0. **Skeptic pre-pass on T-01 (read-only subagent, 20 min max).** Review `uaccess`, `exec`, the ISR/fault path,
   paging and ring-3 entry against INV-03/06/12. Known gap to confirm: `badptr` covers crossing `USER_TOP` but
   not a buffer that starts in a mapped page and runs into an **unmapped page below `USER_TOP`** (the gap after the
   data pages), which is the case the multi-page walk exists for. Fix confirmed bugs first, each with a test.
1. **Executor lifecycle (M1).** For each request: fresh address space from the embedded image (D-41 layout,
   zeroed frames, TLB flush), fixed capability set from the compiled-in policy, enter ring 3, destroy on `exit`,
   fault or quota. **Tick quotas:** per action (5 s *(prov.)*) and per request (60 s); an internal
   `exec_action_boundary()` resets the action quota (T-03b calls it from `agent_recv`). Test builds may shorten
   both through a boot option so the suite stays fast; production defaults are fixed in code. Kernel console:
   `ring3> ` prompt; in test images `run <prog>` starts a test program as a request.
2. **Hardened syscalls (M1).** The full ARCHITECTURE §3 syscall table and error codes; numbers not yet backed by a
   driver (`cell_*`, `agent_*`) go through `decide()` and then return `-ENOSYS`. `uaccess` for every pointer and
   bounded NUL-terminated string copies. Add the missing spanning case from step 0.
   **Fault containment (INV-06):** test programs for null deref, kernel write, `cli`, `hlt`, invalid opcode,
   divide by zero, stack overflow (hits the guard page): each ends with `PROC_FAULT`, the next request still runs.
   **Syscall fuzzer (INV-03):** a seeded user program, 10,000 calls with random numbers and arguments (it may call
   `exit` only at the end): 0 panics, only valid results or error codes, uptime advancing.
3. **Policy engine as a pure function (M2).** `kernel/policy/policy.{c,h}`: `decide(const state*, const event*,
   state* next, decision* out)`, freestanding C with **no kernel headers, no globals, no clock reads**: the tick
   arrives inside the event. Events: `EXEC_START`, `EXEC_END`, syscall request (with `uaccess_ok`), console line,
   confirmation answer/timeout, timer tick, device telemetry sample (R1–R8). Decisions and reasons exactly as ARCHITECTURE §3 "Audit and event
   tape". The kernel turns every policy input into an event (a `tape_record(event)` hook: a COM1 debug line in
   test builds now; `EVENT` frames in T-03b). **Host build:** `make host-policy` builds `build/host/policy_test`
   (unit tests) with the system compiler from the same source; pytest runs it.
4. **Capabilities, objects, taint (M2).** Default-deny bitmask (`CAP_CONSOLE`, `CAP_OBJ_READ`, `CAP_DEV_READ`,
   `CAP_DEV_MOVE`, `CAP_DEV_HMI`, `CAP_AGENT_LINK`), fixed at executor creation from `kernel/policy/`; no syscall
   changes it. Object store per ARCHITECTURE §3: 16 slots, name ≤ 23, ≤ 2 KiB, trust labels and rules; initial
   objects `cell_spec` (limits text), `maint_notes` (the planted instruction text from RING3_CONTEXT §2),
   `scratch_0..3`, `audit_log`. **Taint (D-27):** reading an untrusted object sets `TAINTED` for the rest of the
   request; while tainted every write and every motion (`cell_fan` > 0, `cell_servo`) needs confirmation on top of
   all other rules; `cell_halt` and `cell_fan(0)` never need it; nothing clears taint.
5. **Confirmation (M2).** Kernel prints `CONFIRM: <prog> wants <call>(<args>)[ tainted]. Allow? [y/N]`, takes the
   **next console line** (`y`/`yes` allow; anything else or 30 s *(prov.)* timeout = no). The wait idles with
   interrupts on (D-41e). Test builds may shorten the timeout through a boot option.
6. **Audit.** Every decision → record `{seq, tick, syscall, target, decision, reason, result, tainted}`, appended
   to `audit_log` (kernel-written text, bounded: keep the newest lines) and printed on COM1 in test builds.
   Banner prints the policy hash (SHA-256 of `kernel/policy/` sources, computed at build time).
7. **Device safety rules in `decide()` (M3, pure logic only; the driver is T-04).** ARCHITECTURE §3a "Kernel
   safety policy": servo 30–150°, ≤ 30° per command, ≥ 200 ms apart; fan 0–80 %, ramp ≤ 20 %/s, first fan > 0 per
   request needs confirmation; presence interlock (< 100 mm, **`0xFFFF` = not clear**, D-43), stale > 500 ms;
   E-stop latch (revokes motion until a human console reset **and** the button reads released); lease on every
   tick event → `AUTO_HALT` decision when stale, presence or E-stop while moving; `cell_halt` always allowed
   (INV-16). All limits are named constants marked provisional (T-06 measures the fan's minimum spinning duty).
   Host-tested with synthetic telemetry sequences. If M3 isn't reached by 9 PM ET, stop and report; T-04 takes it.
8. **Kernel ↔ host decision match.** A scripted QEMU run (test programs + console answers) prints its event tape and
   decisions; a pytest feeds the same events to `build/host/policy_test --replay` and requires identical decisions
   in order. (This is the seed of `ring3 replay`, INV-10.)
9. **Permissive build.** `make POLICY=permissive` per ARCHITECTURE §7: banner and every audit line say
   `PERMISSIVE (EVAL ONLY)`, different policy hash. Default build unaffected.
10. Evidence, STATUS, report.

## Don't
- Put any allow/deny logic outside `kernel/policy/`, read a clock or global state inside `decide()`, or let a
  syscall add a capability.
- Weaken a check, quota or test to make something pass; give the bridge (COM2) any way to answer a confirmation.
- Build the COM2 link, bridge, `agentsh`, device driver or anything in `firmware/` (later cards).
- Push, read `.env*`, install plugins/hooks, or edit `.claude/settings.json`.

## Acceptance (binary)
- A1 `make`, `make test-kernel`, `make host-policy` build with zero warnings under `-Werror`.
- A2 `uv run pytest` and `uv run ruff check .` pass; whole default suite < 120 s.
- A3 Fault containment: all seven fault programs end with `PROC_FAULT` (correct vectors), the request after each
  still runs, uptime advances, 0 panics. Spin → `LIMIT` on the action quota; a program that crosses action
  boundaries but runs too long → `LIMIT` on the request quota.
- A4 `badptr` covers all D-41 cases **plus** the mapped-to-unmapped-below-`USER_TOP` span and an unterminated
  string; every case → `-EFAULT`/`-EINVAL`, no kernel page fault. Syscall fuzzer: 10,000 calls, 0 panics.
- A5 Host `policy_test`: one test per row of the ARCHITECTURE §3 object table and syscall-capability table
  (INV-04), default deny for an empty cap set, no escalation path, taint forces confirmation and can't be cleared
  (INV-15), `cell_halt` always allowed even tainted or under E-stop (INV-16), and every device rule in step 7
  including `0xFFFF`, stale, E-stop latch + reset-with-button-released, ramp, and tick-driven `AUTO_HALT`.
  Plus one test per design rule R1–R8, including: presence/stale/E-stop appearing during a pending confirmation →
  denied after "y"; fan 0→80 after a long idle → denied; same-tick 0→20→40 → second step denied; negative duty →
  `DENY_ARG`; `uaccess_ok = false` → `DENY_FAULT` with state unchanged; `AUTO_HALT` audited once per hazard; a
  silent tick leaves the state byte-identical.
- A6 QEMU confirmation tests (INV-05): `y` allows, `n` denies, timeout denies, each audited (`CONFIRM_YES`/`NO`);
  a `y` typed **before** the prompt appears doesn't answer it (R10); the action quota doesn't kill a program
