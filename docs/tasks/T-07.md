# T-07 Camera witness: printed gauge, ArUco dial frame, SAM 3.1 check, closed loop with Muse Spark
Builder: Opus 5.5 / high · **Part A** new terminal, Nov 2 (offline, can run in parallel with T-03b) · **Part B** Nov 3
after T-04 (camera + real cell + paid SAM calls) · D-22, D-29, D-39c, D-42e, D-56

Goal: after a physical servo move, the bridge photographs the printed RING3 gauge, finds the dial with 4 ArUco
markers in that same frame, asks SAM 3.1 where the servo arm is, and reports PASS / FAIL / CAN'T VERIFY for the
commanded zone. The result goes back to Muse Spark as the observation for its `witness` op. The witness never changes
a kernel decision (INV-14).

`docs/LINK_ABI.md`; `docs/evidence/T-03a/README.md`; `docs/DECISIONS.md` D-22, D-24, D-29, D-39c, D-42e, D-47,

## Verified SAM facts (D-56)
- `POST https://api.meta.ai/v1/responses`, Bearer auth, `"model": "sam-3.1"`; `input` = one user message with an
  `input_text` (a short noun phrase, e.g. "white plastic arm") and an `input_image` whose `image_url` is a **base64
  data URL** (no hosting needed); `stream` may be false.
- Output: one text line per image, records separated by commas, each
  `OBJECT_ID <|box;x1=..;y1=..;x2=..;y2=..;w=..;h=..[;c=..]|><|mask;x=0;y=0[;c=..];data=H,W,<enc>payload|>`.
  Box corners are source pixels (top-left origin). `metadata.include_confidence: "true"` adds `c` (0–1). An empty
  `output_text` means "concept not present" (a normal result). The mask payload is base85 with an encoding marker;
  its internal scheme isn't documented beyond "decodes to a row-major 0/1 raster", so **use the box geometry for the
  angle** (below) and treat the mask as optional.
- Price: **$2.50 per 1,000 images** (https://dev.meta.ai/docs/pricing-rate-limits); add to `config/models.toml` with
  the source and date; reserve one image per check before the call.

## Part A: offline (no camera, no paid calls, no kernel changes)
Two-terminal rules if T-03b is running: touch only `bridge/ring3bridge/witness/`, `hardware/gauge/`,
`tests/witness/`, `tools/witness_capture_win.py`, `config/models.toml` (the `sam-3.1` entry only),
`docs/evidence/T-07/`, and `pyproject.toml`/`uv.lock` (only to add `opencv-python-headless` and `numpy`; tell the
user). Scoped tests. STATUS once at the end.
1. **Gauge generator** (`hardware/gauge/make_gauge.py` → `hardware/gauge/ring3_gauge.pdf` + PNG): A4/Letter at 100 %
   scale; a dial (radius ≥ 70 mm) with the servo pivot marked, three labelled zones **LOW / MID / HIGH** covering the
   kernel's servo range 30–150° (40° each), a visible **boundary band** around each zone edge, "RING3" text, and
   **4 ArUco markers (DICT_4X4_50, IDs 0–3)** at known positions around the dial (≥ 30 mm each). The dial geometry
   (pivot, zone angles, marker corners in mm) is written to `hardware/gauge/geometry.json`, which the witness uses.
   No cutting or holes (D-24): the servo lies flat on the paper with its shaft over the printed pivot.
2. **Dial frame** (`witness/dial.py`): detect all 4 markers **in each frame** (fewer than 4 → `CAN'T VERIFY: MARKERS`),
   compute the homography to gauge millimetres, warp-crop the dial region. No stored reference frame.
3. **SAM adapter** (`witness/sam.py`): builds the request above from the cropped JPEG; parses the record grammar
   strictly (bounded lengths, integers, a record the parser doesn't understand → `CAN'T VERIFY: SAM_FORMAT`); uses the
   T-03a transport (key only inside the transport, redirects refused, headers never logged) and the ledger (one image
   reserved first). **Fake transport only in Part A.** Parse records with a bounded regex for
   `<id> <|box;…|><|mask;…|>` (**not** a comma split: mask data contains commas); box/mask coordinates strict integers;
   `c` a bounded decimal in [0, 1]. `sam.py` never reads `MODEL_API_KEY`: it takes an **injected transport and ledger**
   (D-58, INV-09); Part A doesn't edit `bridge/ring3bridge/models/` (T-03b may be in it), Part B wires the real one.
   HTTP 401/403 and transport errors **propagate and stop the run** (INV-09), never become CAN'T VERIFY.
4. **Arm angle from the box** (`witness/angle.py`, D-58): exactly one plausible record required (0 → `CAN'T VERIFY:
   NOT_FOUND`; **2 or more records that pass the arm-shape filter, overlapping or not** → `CAN'T VERIFY: AMBIGUOUS`; a box
   that doesn't have one edge near the pivot and the opposite side near the arm's radius → `CAN'T VERIFY: SHAPE`).
   Angle = direction from the pivot **through the box centre** (in dial coordinates), not the farthest corner (that
   jumps by the arm's half-width around 90°).
5. **Zone + verdict** (`witness/verdict.py`): calibrated angle → zone (LOW 30–70°, MID 70–110°, HIGH 110–150°);
   ±5° *(prov.)* bands at **all four edges** (30, 70, 110, 150) → `CAN'T VERIFY: BOUNDARY`; below 25° or above 155° →
   `FAIL` (never PASS); `PASS` = the commanded zone, clear of every band; `FAIL` = a different zone, clear of the bands. Stale frame,
   failed calibration, low confidence → `CAN'T VERIFY`. **CAN'T VERIFY is never upgraded.**
6. **Calibration maths** (`witness/calibrate.py`): from 5 (commanded angle, measured dial angle) pairs, fit a linear map;
   residual above a limit → witness disabled for the session (reported, never guessed).
7. **Synthetic fixtures + INV-14 tests** (`tests/witness/`): render the gauge with a drawn arm at known angles under
   perspective, blur and lighting changes; marker covered; arm missing; two arms; arm on a boundary; a recorded-style
   SAM text line for each case (fake transport). `test_inv_14_cant_verify_cases` (markers missing, not found, two
   candidates, boundary band, bad calibration, unparseable SAM line) and `test_inv_14_not_in_decision_path` (static:
   nothing in `witness/` writes to the kernel link or imports the link writer).
8. **Windows capture helper** (`tools/witness_capture_win.py`, D-39c): runs on **Windows** Python with OpenCV; on request
   grabs one still from the C922 and writes it as JPEG to a shared folder the bridge can read through `/mnt/c/...`
   (request/response via files in that folder; path from an environment variable, never committed). **Fresh frames only
   (D-58):** each request carries a nonce; the helper discards buffered frames (`grab()` ≥ 5 times) before decoding,
   writes `<nonce>.tmp.jpg` and renames it atomically to `<nonce>.jpg`; the bridge rejects a missing, old or
   mismatched file as `CAN'T VERIFY: STALE_FRAME`. Also a 2-minute
   check in Part B whether the webcam simply works inside WSL (if yes, the helper isn't needed). No network listener.

## Part B: camera, calibration, closed loop (Nov 3, after T-04; user present; paid SAM calls on the user's "go")
1. User prints the gauge at 100 %, lays the servo flat with its shaft on the pivot, uses the **single long horn** as
   the arm, and places the C922 on its tripod looking down at the gauge as steeply as practical (all 4 markers in view).
   The helper or WSL capture works.
2. **Calibration through the kernel:** a `ring3 calibrate --budget-usd <x>` mode acts as a scripted model (no Muse
   call): it sends `servo_set` actions through the normal bridge → kernel → `agentsh` path, **starting from the current
   `STATE.servo_cmd` and stepping ≤ 30° at a time** to 5 angles (e.g. 60, 75, 90, 105, 120; ≥ 200 ms apart), so the
   kernel enforces and audits every move; after each, wait for the settled telemetry + 500 ms, capture, reserve, SAM,
   fit. Report the residual. It makes paid SAM calls, so **the user runs it** (D-57); add `uv run ring3 calibrate` to
   the settings deny list like `ring3 run`.
3. **`witness{}` op in the run loop:** the bridge **intercepts `witness` before ACTION encoding: zero COM2 frames**
   (no kernel action; nothing physical). It needs a preceding **kernel-allowed** `servo_set` in this request (observation
   result ≥ 0); that move's angle is the commanded zone. It waits for `STATE.servo_cmd` to match + 500 ms; otherwise
   `CAN'T VERIFY: NO_MOVE`. Then it captures, checks, logs a `witness` record (commanded zone, measured zone, verdict,
   reason, angles and residuals as **integers in millidegrees**, image hash as a blob), and returns the structured
   result as the observation. Witness calls count toward the bridge's per-request turn limit so the loop
   stays bounded. Context pack **agent-v2**: after a servo move, call `witness`; on `FAIL`, call `halt` and report.
4. **Checks (user present):** 10 commanded moves across the zones → PASS rate recorded; **arm held by hand** during a
   move → `FAIL` (never PASS); servo signal wire unplugged → `FAIL`; one marker covered → `CAN'T VERIFY: MARKERS`;
   camera nudged between checks → still works (markers per frame). Save images, SAM lines, verdicts.
5. **Live closed loop with Muse Spark (user's "go"; `--budget-usd 0.50`):** "move the gauge to MID and confirm it
   really moved"; then the same with the arm held by hand → the model sees `FAIL` and halts/reports. `CHAIN OK`, spend
   estimate, no secrets in the run directory.
6. **Optional, only if everything above passes and time allows (D-32 cut order):** try sending the overlay image to
   Muse Spark as `input_image`; `[UNVERIFIED]` until shown.

- Commit absolute paths, the user's name, or images showing a person.
- Touch `kernel/`, `user/`, `firmware/`. Make paid calls in Part A.

## Acceptance (binary)
- A1 (Part A) Gauge PDF + geometry generated; INV-14 tests and the synthetic-fixture tests pass; parser rejects malformed
  SAM lines; ledger reserves one image before every SAM call (fake transport).
- A2 (Part B) Calibration residual reported and under the limit, or the witness disables itself with a clear message.
- A3 (Part B) Blocked arm and unplugged signal never PASS; covered marker → CAN'T VERIFY; PASS rate over 10 moves
  recorded with counts.
- A4 (Part B) Live closed loop: the model receives the witness result and reacts to a `FAIL`; `CHAIN OK`; spend ≤ budget.
- A5 Commits: real `Builder:` trailer, only this card's paths.
