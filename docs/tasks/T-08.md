# T-08 Kernel console screen (VGA text) + styled bridge timeline
Builder: Opus 5.5 / high · new terminal · Nov 3, **only after T-04 steps 7 and 8 are done** (the live run uses the
image as it is) · D-13, D-32 (first to cut), D-66, D-66a · Pre-review: waived by the lead (display only, no trust
boundary); Codex Gate A still reads the diff.

Goal: the QEMU window shows the kernel's own 80x25 status screen in the RING3 console style, driven only by real
kernel and cell data, and the bridge timeline gets an optional styled mode for filming.

Context: `docs/design/astra-ui-spec-raw.md` (the design reviewer's mockups, field table, motion rules, video notes);
**this card's corrections override it**. `CLAUDE.md`; `docs/ARCHITECTURE.md`; `docs/INVARIANTS.md` (rule 11 wording);
`docs/evidence/T-04/README.md` (the panel's verdict words and reason phrases); `docs/DECISIONS.md` D-13, D-32, D-47,
D-66, D-66a.

## Corrections to the design spec (binding)
1. Calls shown are the real ones only: `cell_status`, `cell_fan(n)`, `cell_servo(n)`, `cell_halt`, `cell_lcd`,
   `read_object(name)`, `write_object(name)` (use whatever names the kernel/agentsh already print). There is **no**
   `cell_dist()`; the distance comes from telemetry / `cell_status`.
2. Fan duties in examples and tests are 0 or 50-80 (D-47). Never show `cell_fan(30)` as a normal request.
3. The E-stop does **not** kill the executor. `EXEC KILLED` appears only when the kernel really killed it (fault,
   tick quota). After an E-stop the executor line shows its real state (running or idle).
4. Verdict words and reason phrases come from **one table shared with the LCD panel** (T-04's driver); don't add a
   second vocabulary. Words: ALLOW, DENIED, ASK, CONFIRMED, DECLINED, AUTO HALT, BOARD BOOT. Outcomes: DONE, REFUSED,
   STOPPED, ERROR.
5. Scales: servo dial 0-180 deg with the kernel's 30 and 150 limits marked; distance bar span 0-400 mm (longer =
   full bar), `NO ECHO` printed as words with an empty bar.
6. Telemetry age, memory, uptime, decision count, taint, link and presence come from existing kernel state. If a
   field isn't available without new trust-boundary code, leave it out rather than estimate it.
7. Timeline (B) uses the bridge's own host time column as it does now (not kernel uptime).

## Do
1. **Pure renderer** (`kernel/ui/` or `kernel/drivers/vga*`): `render(const struct screen_model *m, uint16_t
   cells[25][80])` as a pure function (no I/O, no globals), compiled for the kernel **and** the host like `decide()`.
   The model is a plain struct snapshot (uptime, executor state + request id, free KiB, decisions logged, last 4
   decisions, banner word/detail/start tick, taint, console window lines, cell telemetry fields, link, age).
2. **Kernel side:** a VGA text driver writing 0xB8000 from a back buffer, **only cells that changed**, at most every
   tick (100 Hz), outside interrupt context where possible; blinking attribute off; cursor hidden or steady. The
   snapshot is filled from existing state at the audit/decision path and the device driver's latest frame (read-only
   copies; **no change to `decide()`, the policy state, the syscall gate or the frame parsers**). Console output is
   mirrored into the console window (rows 7-13); COM1 output stays exactly as it is (tests read COM1).
3. **Motion** (as the spec's motion table, with the corrections): bars and needle jump to each new telemetry value;
   banner wipe rows 3, 4, 5 at ~0/70/140 ms and hold; ticker shifts on a new decision; age counts up. No movement
   without a real event.
4. **Make target** that opens the QEMU window for filming: `make run-cell-screen` (QEMU display via WSLg; fallback
   `-display curses`, D-39), same serial wiring as `run-cell`.
5. **Bridge styled timeline:** `ring3 run --style console` (opt-in) prints the timeline with 256-colour ANSI, the
   150 ms arrival highlight and the 200 ms outcome pulse, **only when stdout is a TTY**; otherwise (and by default)
   the plain lines exactly as now, so evidence files and tests don't change.
6. **Tests:** host golden tests of `render()` for the three mockup states (exact 80-column text of the expected
   rows), a test that no rendered string contains a banned word (extend `test_inv_11_banned_words` to the new
   files), a QEMU test that boots the screen image and checks the VGA buffer through QEMU's monitor (`xp` / `pmemsave`)
   shows the status bar and a decision word, and a bridge test that `--style console` output to a non-TTY equals the
   plain output byte for byte.
7. Screenshot evidence: one PNG of each state from a real run (QEMU `screendump`), no staged data.

## Don't
- Touch `decide()`, policy state, the syscall gate, `uaccess`, frame parsers, the event log format or the bridge's
  validation/ledger code. Display code only reads copies.
- Draw anything not backed by real data; add decorative animation; use "success", "secure", "safe", "real-time";
  copy any franchise logo, symbol, name or font; use military wording (D-66a).
- Let the screen slow the tick: rendering must stay well under 1 ms per tick (measure it, report it).
- Change COM1 output or the plain timeline (tests and evidence depend on them).
